# Releasing

This fork versions and releases the way upstream MinIO did. Tags are UTC
timestamps generated by `buildscripts/gen-ldflags.go`, so `minio --version`
and `mc admin info` report releases exactly as upstream builds do.

## Branches

- `master` is the trunk. Every change, including security fixes, lands through
  a pull request.
- `release/RELEASE.<time>` branches exist only to backport fixes onto an
  earlier release. Create one from the release tag when a backport is needed.

## Cutting a release

1. Make sure every entry in `security/advisory-matrix.json` is `closed`. The
   release workflow refuses to publish otherwise.
2. Tag the tip of `master` with the current UTC time:

   ```sh
   tag="$(MINIO_RELEASE=RELEASE go run buildscripts/gen-ldflags.go "$(date -u +%Y-%m-%dT%H:%M:%SZ)" \
     | tr ' ' '\n' | sed -n 's/^github.com\/minio\/minio\/cmd.ReleaseTag=//p')"
   git tag -s "$tag" -m "$tag"
   git push origin "$tag"
   ```

3. `.github/workflows/release.yml` checks the tag and the advisory gate, then
   runs the tests, `go vet` and `govulncheck`. It builds the container image
   with the tag's ldflags, signs it, and publishes a GitHub release with a
   `release-manifest.json`.

## Hotfixes

To backport a fix onto an earlier release `RELEASE.<time>`, follow upstream's
`make hotfix` convention:

```sh
git switch -c "release/RELEASE.<time>" "RELEASE.<time>"
git cherry-pick <fix commits>
git push origin "release/RELEASE.<time>"
tag="RELEASE.<time>.hotfix.$(git rev-parse --short HEAD)"
git tag -s "$tag" -m "$tag"
git push origin "$tag"
```

The workflow accepts hotfix tags only on commits that are on a `release/*`
branch.

## Security advisories

Vulnerabilities are reported privately through the repository's security
advisories (see `SECURITY.md`). A fix is developed in the advisory's private
fork, merged, and released. The advisory is then published with the release
that contains the fix.
